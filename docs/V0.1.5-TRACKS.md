## Remaining — 4 parallel tracks
Confirmed build order within the session cluster: **G→C→D→E→F→H** (G done). Two new phases added 2026-06-09: **I** (naming), **J** (model picker).

Why 4 tracks and not 7 parallel: the model picker (J), hooks (C), and templates (E) all rewrite the **same** hot files
(`claudeCommand` argv + the New Session dialog + `createSessionBody`). Splitting them = merge hell. So one agent runs
**J→C→D→E serially** (Track A); the three genuinely-disjoint phases (naming, fleet, update) run in parallel.

| Track | Phases | Owns | Conflict |
|---|---|---|---|
| **A — Session Launch & Intelligence** | J→C→D→E (serial) | proto SessionCreatePayload, `claudeCommand` (`--model` + `--settings`), sessionapi createSessionBody, store telemetry, NewSessionDialog, session cards, `/api/hooks/state` | self-contained |
| **B — Session Naming** | I | Sidebar context-menu + rename, new `PATCH /api/sessions/{id}` title, store title setter, auto-name | low |
| **C — Fleet & Wake** | F | wake.go, devices, placement, fleet UI | none |
| **D — One-Click Update** | H | internal/update, hub update endpoint, proto TypeUpdate, agent update handler, banner (reuses releases.go) | none (additive proto) |
